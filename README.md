# 淘玛特产品组合器（Product Composer）

> 状态：v1 重构中 · 方向已从“立项专家/飞书表”剪枝为“产品资产录入 + 模块组合工作台” · 2026-05

## 这是什么

产品部内部用的新品构思工作台。先把“产品录入”做无痛：导入货盘或手动写一句想法，系统自动拆出产品资产、模块、品类地图和可复用素材，再辅助生成产品概念卡。

它不是立项审批、评分卡、任务分发或飞书多维表系统。但如果接入运营提案，必须增加“机会证据闸口”：先判断运营提案是否值得进入产品组合器，不能让所有运营想法都直接消耗产品部产能。

## 当前路线

1. **货盘导入**：从现有 xlsx 解析 SKU、品牌、品类、销量、升级思路、竞品链接。
2. **资产沉淀**：自动拆成产品资产表、模块库、品类地图。
3. **产品部入口**：用户用自然语言描述“舒适、包裹性强、某品牌、某风格”等意图，直接进入组合器。
4. **运营入口**：运营提案先过证据闸口，不合理、不完整、属于运营动作的问题先退回，不进入组合器。
5. **模块组合**：AI 只做解析、匹配和解释；关键判断由数据规则约束。
6. **缺口/未起量分析**：从品类地图和产品资产中提供可点击入口，而不是让人填大表。

## 双入口边界

| 入口 | 服务对象 | 先做什么 | 产出 |
|---|---|---|---|
| 产品部构思 | 产品负责人/设计师 | 直接组合模块 | 产品概念卡、模块清单、新模块沉淀 |
| 运营提案 | 运营/渠道/销售反馈 | 先做机会证据闸口 | 通过/补证据/退回/合并到已有产品迭代 |

运营提案闸口不是评分卡。它只回答一个问题：**这件事是否值得产品部进入组合器构思新品？**

## 已剪枝

已直接删除旧 `archive/`：原“立项专家”、飞书 01-06 表、评分锚点、任务分发、openclaw 建表脚本全部不再作为路线依据。

## 重要原则

1. **先录资产，再谈 AI**：没有产品资产表和模块库，AI 不能凭空判断。
2. **入口无痛**：用户可以导入货盘、点品类地图、点未起量 SKU，或直接写一句想法。
3. **判断可追溯**：爆品升级、竞品升级、品类缺失、未起量诊断都必须引用 SKU/模块/销量/竞品证据。
4. **先闸口，后组合**：运营提案证据不足时，不生成模块组合，避免“方案很多但立项本身不成立”。
5. **AI 不判生死**：AI 负责解析、匹配、解释和生成草案，不做审批和任务分发。
6. **新内容回流模块库**：被选中的自由创意、外部素材和新方案都带作者标签，沉淀为可复用资产。
